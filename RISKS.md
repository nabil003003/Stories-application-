# StoryForge Studio — Risk Register & Technical Mitigations

This file tracks verified platform realities, unverified assumptions, licensing constraints, and technical performance boundaries.

---

| Risk ID | Category | Description | Severity | Mitigation Strategy |
|---|---|---|---|---|
| **RSK-001** | AI / Licensing | **Chatterbox Model License & PerTh Watermark**<br>Chatterbox Multilingual code is MIT, but model weights license must be documented. Generated audio embeds Resemble AI's PerTh neural watermark. | High | Disclose watermark clearly in UI settings and `LICENSES.md`. Never attempt to strip watermarks. Bundle only verified permissive speech reference clips. |
| **RSK-002** | TTS / Arabic | **Piper Single Voice Arabic Limitation**<br>Piper ONNX provides only one Arabic voice (`ar_JO-kareem`). Multi-character stories cannot fall back to Piper without voice collisions. | High | Implement capability-aware fallback chain: if language is Arabic and >1 character exists, do NOT silently collapse onto one voice. Fail with clear action dialog: "[Install Chatterbox Model] [Assign Shared Voice]". |
| **RSK-003** | Localization | **Arabic Diacritization (Tashkīl) Ambiguity**<br>Undiacritized Modern Standard Arabic causes TTS vowel guessing and incorrect name/verb pronunciation. | High | Implement a `TextNormalizer` pipeline with pluggable diacritizer and user-overridable phonetic dictionary before computing the generation cache key. |
| **RSK-004** | Video / Rendering | **Arabic Shaping & RTL Video Burn-in Failure**<br>FFmpeg standard `drawtext` breaks Arabic letter shaping and reverses word order. | Critical | Subtitle burn-in must strictly use FFmpeg `subtitles` filter linked against `libass`, `libfribidi`, and `libharfbuzz` with bundled fonts (Noto Naskh Arabic / Noto Sans Arabic). Automated golden-frame visual regression test required. |
| **RSK-005** | Performance | **Long-Form Audio Batch Generation Throughput**<br>Generating ~2 hours of narration on consumer GPUs is a multi-hour batch job; on CPU it may be overnight. | Medium | Serialize TTS through single GPU worker; persist chunk status in SQLite; stream progress via SSE; allow user to edit other scenes and listen to completed chunks while background queue runs. Calculate ETA from machine's first 10 chunks. |
| **RSK-006** | Audio Quality | **Stitched Chunk Seam Artifacts**<br>Direct concatenation of chunked TTS creates audible clicks, room-tone jumps, and unnatural pauses. | Medium | Mandatory multi-stage DSP per chunk: silence trim (-45 dBFS), DC offset removal & HPF (70-80 Hz), pre-join peak normalization, explicit pause insertion for punctuation, and 10-20ms crossfading. |
| **RSK-007** | Security | **Local API Hijacking & Prompt Injection**<br>Local HTTP servers without auth are vulnerable to cross-site requests or malware; story text containing instructions could hijack AI assistant. | High | Random port + 32-byte Bearer token required on all endpoints. Strict whitelist AI operation schema with entity validation; user story text is strictly treated as data, never inserted into assistant system prompts. |
| **RSK-008** | Packaging | **Bundled Python Sidecar & Native Dependencies**<br>Packaging PyTorch, CUDA runtime, and ONNX Runtime into a zero-prerequisite Windows installer can lead to bloated installer sizes (>3 GB) and DLL path mismatches. | High | Use PyInstaller / Briefcase with selective dependency bundling, dynamic CUDA detection with graceful CPU fallback, and test on clean Windows 11 VM with no Node/Python. |
