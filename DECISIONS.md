# StoryForge Studio — Architecture Decision Records (ADR)

This file is an append-only log of architectural and technical decisions made during the lifecycle of the project.
Format: `Date | Decision | Alternatives rejected | Why | Reversible?`

---

| Date | Decision | Alternatives Rejected | Why | Reversible? |
|---|---|---|---|---|
| 2026-09-18 | **ADR-001: Shell Choice** — Use Tauri 2 (Rust) targeting Windows 10/11 x64 as primary shell. | Electron, Flutter, Qt, Native WinUI. | Electron has massive RAM and bundle overhead; Tauri 2 provides lean native webview, Rust security sandboxing, native sidecar supervision, and OS credential store access. | No |
| 2026-09-18 | **ADR-002: Frontend Stack** — React 18 + TypeScript (strict) + Vite + Tailwind CSS + shadcn/ui + Zustand. | Next.js, Vue, Svelte, Redux. | Standardized modern desktop-grade stack; Vite provides sub-second HMR; Zustand offers minimal-boilerplate state management ideal for virtualized timeline and story nodes; zero unnecessary SSR. | Yes (modular UI) |
| 2026-09-18 | **ADR-003: Backend Sidecar** — Python 3.11 + FastAPI packaged as Tauri sidecar via PyInstaller and managed via `uv`. | Node.js backend, C++ embedded engine, Go sidecar. | Deep learning TTS ecosystem (PyTorch, Chatterbox, Piper) is Python-centric. FastAPI provides async I/O, SSE progress streaming, and OpenAPI schema generation for TypeScript types. `uv` ensures reproducible Python 3.11 isolation without requiring user-installed runtimes. | No |
| 2026-09-18 | **ADR-004: Dual Audio Engines** — Frontend Web Audio API for interactive scrubbable preview; Backend Python/FFmpeg for authoritative master render. | Frontend-only render, Backend-only audio streaming for UI. | Streaming live audio from backend over IPC induces seek latency; Web Audio API gives immediate 60fps scrubbable feedback. Contract: Both consume identical `TimelineDocument` JSON and backend precomputes narration ducking envelope once to guarantee parity. | No |
| 2026-09-18 | **ADR-005: Audio Format Policy** — 48 kHz, float32 internal working format (mono voice, stereo music/sfx). FLAC intermediate chunk caching. | 44.1 kHz, 16-bit WAV, MP3 intermediate cache. | 48 kHz is broadcast and video standard; float32 avoids clipping during DSP/normalization stages. FLAC offers lossless storage with ~50% disk footprint reduction compared to raw WAV. | Reversible via format migration |
| 2026-09-18 | **ADR-006: Job Queue & Concurrency** — Single serialized GPU worker for TTS; CPU pool (`cpu_count - 2`) for DSP and FFmpeg. | Multi-threaded parallel GPU inference, Celery/Redis. | Concurrent TTS inference on a consumer GPU triggers VRAM Out-Of-Memory (OOM) crashes rather than speed gains. Single-worker queue with SQLite persistence ensures crash resilience. | No |
| 2026-09-18 | **ADR-007: Sidecar Security & Port Binding** — Dynamic localhost port (`127.0.0.1:0`) + cryptographically random 32-byte Bearer token. | Static port (e.g. 8000), unauthenticated localhost API. | Static ports clash with other software; unauthenticated localhost APIs allow any local malware or browser script to hijack the audio studio and invoke commands. | No |
| 2026-09-18 | **ADR-008: Project Storage Format** — `.storyforge` directory bundle containing `project.json`, `project.sqlite` (metadata & relative paths), and structured subdirectories (`originals/`, `generated/`, `renders/`, etc.). | Single monolithic SQLite file, raw files without database. | Binary blobs degrade SQLite performance; pure flat files lose relational integrity. Directory bundle keeps project self-contained, portable, atomic, and inspectable. | No |
| 2026-09-18 | **ADR-009: Composite Cache Key** — SHA-256 hash over provider, model version, voice ID, voice ref hash, language, normalized text, settings JSON, seed, postprocess version, and audio format version. | Text-only hash, simple timestamp cache. | Ensures precise invalidation: changing music doesn't touch voices; tweaking character pitch touches only that character; changing DSP algorithms automatically invalidates via `postprocess_version`. | No |
| 2026-09-18 | **ADR-010: Subtitle Burn-In via libass** — Use FFmpeg `subtitles` filter with libass, FriBidi, HarfBuzz, and `.ass` scripts instead of `drawtext`. | FFmpeg `drawtext` filter. | `drawtext` fails on Arabic script (does not perform contextual shaping and reverses RTL glyphs). Libass correctly formats Arabic, French diacritics, and English captions. | No |
